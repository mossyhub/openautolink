# Source-qualified CarPlay UI restriction policy

This is an **off-by-default restriction-control capability**, not a literal gear protocol or safety certification. Settings → Connection → CarPlay → **Vehicle-based UI restrictions** enables both the declaration and writer for the next session, even in an ordinary build without a build opt-in. The build property `-PoalCarPlayDrivingRestrictions=true` remains a separate explicit lab override; its default stays false, and an opted-in build visibly keeps the capability on. With neither saved capability nor build opt-in, the legacy no-declaration/no-writer behavior is retained.

Under the same CarPlay group, **Always in Park** is a separate persisted choice, default **OFF**, available only when restriction control is enabled. This parked-use override releases only main-screen limited UI, including when actual gear is not Park or absent. It never changes raw gear, its source/status/timestamps, Android Auto's independent preference, secondary-screen restriction, or parked-video permissions. Its finite reason is `user_override`, never `actual_park`. Disabling the capability in normal builds also clears the override draft. Both controls use the existing **Save changes** transaction: editing has no current-session effect; save changes, then reconnect your phone (wireless reconnects automatically; for USB, unplug and reconnect). Successful persistence precedes reconnect, and the new session freezes one matching declaration/writer policy. A failed save must not restart or discard the draft. Unknown fields do not opt in; missing, malformed, numeric, null or quoted-Boolean safety choices fail closed to default OFF. Parked video remains disabled.

## Chosen OAL policy, not an OEM calibration claim

When opted in, every advertised main/secondary display starts with `limitedUI=true` and the four explicit limitable UI elements. Main-screen commands name `AirPlayInfoPlist.MAIN_UUID`; an advertised secondary receives its exact `ALT_UUID` and stays restricted even in Park. Omission/default-display fallback is deliberately avoided. This is a conservative OAL lab choice, not proof of country-specific compliance or of secondary-display UI behavior on the owner's phone.

With Always in Park OFF, only actual `GEAR_SELECTION` (`0x11400400`) **Int4 Park** can release main-screen UI. Raw1 Neutral, raw2 Reverse, raw8 Drive, every other/missing/wrong-type value, invalid/unavailable status, absent metadata, inactive subscriptions, non-VHAL source, nonpositive/mismatched registration generation, missing/future timestamps, or expired authority restrict. Neither speed0 nor parking brake nor a derived `driving=false` grants Park privileges.

A new explicit `statusReadElapsedMs` records completion of the existing serialized real `getProperty` lane. The lane now includes GEAR_SELECTION as well as existing EV properties; it verifies gear result property ID and area0, preserves the actual HAL event timestamp, and retains the existing lifecycle/generation/permission/sequence fences. A fresh AVAILABLE ONCHANGE read may confirm an unchanged old Park event without pretending that event just occurred. All other observations need a fresh source timestamp as well as fresh receipt. The local budget is 15 seconds, accommodating the existing five-second read interval; the bridge's 250ms timer restricts after expiry even if upstream stops emitting entirely. A blocked Binder lane cannot keep Park authorized indefinitely.

## Ownership and receipts

Both real USB and wireless runtimes pass the exact session's ready-only writer and freeze the same saved/build policy into `/info`. The ordinary intake's authentication and encrypted-event readiness own delivery; no command is queued before readiness. A readiness edge replays the currently eligible state. In real mode source/status loss or non-Park updates revoke it; the timer handles silence. The writer rechecks Park/source/owner (or this owner's explicit frozen user override) **inside the actual event writer lock**, so a real-mode unlock queued behind another command is clamped to restricted if it expires or loses authority. A clamped write is not acknowledged as an unlock.

StateFlow/latest-value collection is bounded. Successful states deduplicate; failed writes are retried only on a subsequent source-sequence/readiness/desired-policy change, not a busy timer loop. Each bridge owner exports at most64 finite receipts:

`carplay-restriction reason=actual_park limited=false result=transmitted count=1`

Other reason enums: absent, metadata, source, generation, inactive, status, timestamp, stale, not_park, user_override. The count is saturating and means completed local writer bundles, not iPhone reception, UI state, safety certification or transmission of literal gear. Revoke suppresses late receipts nonblockingly. Retirement waits for admitted IO and exact job exit; it does not acknowledge a timeout while old IO remains live. Existing receiver/runtime failed-close retention remains in force.

## Physical acceptance still required

1. Parent alone manages the authorized tablet/car and iPhone. Use a fresh opted-in session; keep EV prediction and parked video out of scope.
2. Require a completed `carplay-restriction` transmission receipt and matching source/generation/status evidence before attributing anything to the bridge. A tablet with no actual VHAL gear source must remain restricted; it is not a Park source. Separately labelled replay fixtures are a different experiment and must not silently rewrite real provenance.
3. In a safely stationary vehicle with actual Park, open a **new** CarPlay Maps destination search and show the software keyboard; verify it accepts a test character. Do not use a cached already-open keyboard as the only discriminator.
4. In a controlled stationary test, remove/invalidate the gear source or select an authorized non-Park/Neutral replay case without moving the vehicle; require `limited=true` and a newly attempted keyboard to be unavailable. Do not ask someone to operate a keyboard while driving. Restore fresh real Park and require reopening the keyboard to work again.
5. Repeat fresh reconnect/readiness, USB and wireless when their actual ingress is available. Confirm secondary display stays restricted if advertised. No secondary display means this part is unexercised, not passed.
6. **Pass:** fresh actual-Park unlock + non-Park/source-loss restriction + reconnect replay all agree with newly exercised phone UI and local completed-write evidence. **Fail:** eligible transmitted transitions disagree with fresh phone UI. **Inconclusive:** no eligible source, no actual event write, stale/cached UI, incomplete reconnect, or no accessible phone interaction. Host AEAD/bplist and ZIP tests cannot upgrade inconclusive to phone-proven.
